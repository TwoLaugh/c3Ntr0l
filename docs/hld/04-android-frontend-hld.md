# Android Frontend HLD

## 1. Role

The Android app is the main mobile execution and capture surface.

It should make the user's day easy to live:

- see today's plan
- capture new input
- complete/partial/skip tasks
- do quick review
- receive future reminders/notifications

The Android app should not try to be the full admin cockpit in V1.

## 2. Recommended Stack

- Native Kotlin
- Jetpack Compose
- Retrofit/Ktor client
- Local cache via Room if needed
- Google sign-in support

Native Kotlin Compose is preferred because later versions may become more system-adjacent, especially if launcher, notification, accessibility, or intent-filtering features are explored.

## 3. Main Screens

### 3.1 Today

Primary screen.

Shows the current daily plan.

Mobile default could use a compact timeline/card-like block list, even though the conceptual model remains a schedule.

Actions:

- complete
- partial
- skip
- move later
- open details
- switch to list mode

The app should minimize taps for common execution actions.

### 3.2 Inbox

Fast capture screen.

The user can type a natural-language note and submit it to the backend inbox pipeline.

The response should be terse:

```txt
Added to Saturday. I will keep it flexible.
```

No cluttered chat history by default.

### 3.3 Task Detail

Task detail should support:

- view notes
- add note
- partial completion note
- edit title/details
- see project/domain
- archive if needed

### 3.4 Daily Review

Mobile daily review should be extremely short.

It should display only the important prompts generated by the backend.

### 3.5 Settings

Minimal V1 settings:

- account
- tone
- default Today view
- AI change visibility

Deeper routine/domain/project editing can live primarily in the web app.

## 4. Offline Behavior

V1 can require network for AI and planning, but the app should ideally cache:

- today's plan
- task states
- recent inbox submissions

If offline, the app can queue simple completion events and inbox messages for sync.

This can be lightweight in V1 and hardened later.

## 5. Design Direction

The app should feel calm and utilitarian.

Avoid:

- gamified streak treatment
- notification-heavy UX
- dense dashboards
- visible AI chat clutter

Prefer:

- clear blocks
- minimal motion
- concise labels
- strong visual distinction between fixed and suggested items
- quick action controls

## 6. V1 Non-Goals

- Android launcher replacement
- notification filtering
- app gating
- message filtering
- accessibility-service automation
- complex offline-first behavior
